# Map-C8：発見物分類別の未報告内訳の監査・検証

## 開始条件と変更範囲

2026年11月7日、`feature/map-report-hold`の`fc5a603`から開始した。
Map-C7は同commitで保存済みで、開始時の作業ツリーはクリーンだった。
今回は分類別の既存集計結果をTypeScriptへ渡し、既存カードへ表示する部分だけを拡張した。
SQL、保存処理、概要総数、勲功値、地図管理は変更していない。

## 集計条件の監査

`ProgressStatsRepository.getForProfile()`は、従来の3クエリでクエスト・発見物と分類別・勲功値を取得する。
発見物の共通CTEはactiveな発見物に、選択中プロフィールの進捗と初回報告履歴を結び付ける。
履歴JOINはプロフィール＋発見物IDで行い、履歴行がなければunknownとして扱う。
進捗と履歴の複合主キーにより、一つの発見物を増幅するJOINにはならない。

現在未報告は、発見済みで、有効な現在報告状態が0の非レリック発見物である。
レリックと特殊自動報告はMap-C7と同じ条件で除外する。保存値が`reported=0`でも自動報告で有効報告済みなら含めない。
地図の関連有無は対象条件にせず、複数地図が対応しても発見物を一度だけ数える。
`report_hold`や勲功値算入資格から未報告の履歴区分を推測しない。

共通CTEは`category_id`ごとに集計し、同じ結果から概要総数と分類別行を作る。
SQLは分類ごとの`unreportedNotReported`・`unreportedConfirmed`・`unreportedUnknown`を既に返していたが、
既存の`mapCategoryStats()`はそれらをTypeScriptモデルへ渡していなかった。
今回は概要総数と同じ変換helperを使って分類別にも`unreportedBreakdown`を渡す。
3つのSELECTテンプレートが基点commitと同一であることを確認した。N+1、全件転送、新しいクエリは追加していない。

## Map-C7との一致と分類NULLの相違

| 区分 | 条件 | 表示 |
| --- | --- | --- |
| 初回未報告 | 現在未報告かつ`not_reported` | 0件でも表示 |
| 再報告待ち | 現在未報告かつ`confirmed` | 原則0件でも表示。分類例外は下記参照 |
| 履歴未確定 | 現在未報告かつ`unknown`または履歴行なし | 1件以上なら表示 |

`unknown + legacy_merit_credit=1`は履歴未確定のままである。
各分類で、現在未報告＝初回未報告＋再報告待ち＋履歴未確定を満たす。
再発見はconfirmedの履歴を保持し、再報告待ちへ戻る。初回未報告は増えない。

Owner確認後の最終調整では、再報告の概念がない「港・集落」「伝承」に限り、再報告待ち0件を省略する。
1件以上なら集計値を隠さず「再報告待ち（要確認）」と確認理由を表示する。値を0へ置換したり他の区分へ移したりしない。
「気象・現象」は地図がなくても再報告可能であり、通常分類と同じ表示を維持する。
分類マスター名の完全一致を用い、部分一致・固定のローカル分類ID・地図の有無では判断しない。
初回未報告と履歴未確定、Map-C7の概要カードは変更しない。

分類NULLは従来から概要総数には含まれるが、分類別カードには含まれない。
SQLの最終的な分類別出力が分類マスターへのINNER JOINであり、NULLのグループは表示行として返らないためである。
今回も新しい「未分類」カードは追加せず、既存の表示対象を維持した。
したがって、概要総数と表示された分類別件数の和が違う場合は、分類NULLの分を区別して確認する。
有効な発見物がない登録済み分類も従来どおり表示しない。

合成DBでは、現在未報告総数9件＝初回3＋再報告3＋未確定3のうち、分類NULLのconfirmedが1件あった。
表示分類は8件＝初回3＋再報告2＋未確定3となり、差1件が分類NULLと一致した。
合成レコードへ分類を割り当てる試験では、総数・勲功値は不変で、表示分類の和が9件となることも確認した。
実データの件数を調べたものではない。

## UI方式の比較と実装

既存画面は表ではなく、進捗バー付きの2列の分類別カードである。
表へ変更して列を加える方式は既存の配置と移動操作の構造まで変更するため採用しなかった。
既存数値の下へ、同じ3名称の小さな内訳行を加える方式を採用した。

既存の総数・発見済み・達成率・未発見・未報告・カード所有、分類順と移動ボタンは維持する。
Map-C7の表示部品と数値・合計チェックを共用し、分類別では説明文を繰り返さず、内訳だけを横並びで折り返す。
分類名を含むアクセシブルなラベルを付け、初回未報告は太字でも区別する。
レリックには内訳を付けず、「報告: 対象外」「カード: 対象外」を維持する。
「港・集落」「伝承」の再報告待ちが1件以上の場合は、現在の報告状態と初回報告履歴の確認を促す短文を添える。
この例外は分類別カードから渡す任意の表示指定だけに適用し、Map-C7の概要カードへは指定しない。

未取得・不正・合計不一致では従来の未報告総数を残し、「未報告の内訳を確認できません。」と表示する。
差分を履歴未確定へ足すなどの補完は行わない。
既存の全カード領域の移動ボタンと、Enterによる移動、Tabによるfocus対象を維持する。
