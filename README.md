# DOL Progress Manager

『大航海時代 Online』のクエスト・発見物の進捗を、キャラクターごとにPC上で管理するWindows向けアプリです。キャラクターは「プロフィール」として登録します。大航海時代データベースから手動で取得したマスターデータを取り込むと、通常の進捗管理はオフラインで行えます。

本プロジェクトはGitHubでソースコードを公開し、Windows x64 Portable ZIPをGitHub Releasesで配布する方針です。配布物の公開状況は[GitHub Releases](https://github.com/guardiancrow/dol-progress/releases)で確認してください。インストーラーを使わず、アプリのフォルダーをコピー・移動して利用できます。

本プロジェクトは非公式のファンツールです。ゲームの開発元・販売元・運営元による公式ツールではなく、それらの組織や大航海時代データベースとの提携・公認を示すものでもありません。ゲーム名、製品名、商標などの権利は各権利者に帰属します。

初めて使う方は「はじめて使う方へ」を順に読み、進捗の登録まで進めてください。日常の操作は「基本操作」、データの保管や更新は各項目を参照できます。

## 主な機能

- プロフィールごとのクエスト・発見物の進捗管理と、プロフィール名・メモの編集
- クエストの検索、達成状態・前提クエスト・必要スキル・オファー方法・都市による絞り込みと並べ替え。選択したスキルの「要求Rank」でも並べ替え可能
- 発見物の検索、分類・発見／報告状態・カード所有状態による絞り込み。報告状態とカード所有状態は独立して管理し、レリックは報告・カードの対象外
- クエスト・発見物の名前の横の情報ボタンから、取り込んだ説明・備考を参照。プロフィールのメモとは別の情報
- 「概要」での進捗集計、冒険勲功値の表示、分類から「発見物」一覧への移動
- 「マスターデータ」での手動取り込み、更新結果・警告・取り込み履歴の表示
- バックアップ／復元、標準保存場所とカスタム保存場所の切り替え

前提状態の判定は保存済みの直接関係と進捗に基づき、ゲーム内の全受注条件を保証しません。詳細は[機能要件](docs/requirements.md)を参照してください。

## はじめて使う方へ

### 動作環境と必要な準備

利用対象はWindows 10／11 x64です。次の2種類のRuntimeが必要です。

- Microsoft Visual C++ Redistributable x64（v14系）：[Microsoft公式のVisual C++ Redistributable案内](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)から導入してください。
- Microsoft Edge WebView2 Runtime：[Microsoft公式WebView2ページ](https://developer.microsoft.com/en-us/microsoft-edge/webview2/#download-section)からEvergreen Runtimeを導入してください。

アプリはRuntimeを自動でダウンロード・インストール・更新せず、案内時にブラウザーも自動で開きません。導入後にDOL Progress Managerを起動し直してください。アプリを削除するときにRuntimeを削除する必要はありません。

Visual C++ Redistributableは、ビルド時のMSVCツールセットと互換のあるv14系x64が必要です。Microsoftの対応条件は、Redistributableの版が使用したMSVC Build Toolsと同じか新しいことです。古い固定版を必要条件にせず、対応する最新サポート版を使用します。

VC++ Runtime DLLが不足していると、アプリの処理が始まる前にWindows側で起動に失敗する場合があります。その場合、アプリ内の起動前検査や日本語案内は表示できません。WebView2 Runtimeの検出・案内とは別の起動要件です。

利用できるWebView2 Runtimeを確認できなければ、アプリは画面を開く前に日本語の案内を表示して終了します。この場合、データ・設定フォルダーは初期化しません。

SQLiteとWebView2 LoaderはEXEへ組み込まれているため、個別インストールは不要です。

### ダウンロードとファイルの確認

1. [GitHub Releases](https://github.com/guardiancrow/dol-progress/releases)で対象版の説明を確認します。
2. Assets（配布ファイルの一覧）からWindows x64 Portable ZIPと、同じ名前に`.sha256`を付けたファイルを取得します。
3. 下記の方法でZIPのSHA-256を確認します。一致しない場合は起動・更新せず、取得元と対象版を確認してください。

v0.3.0のファイル名は`DOL-Progress-Manager_0.3.0_windows-x64_portable.zip`と`DOL-Progress-Manager_0.3.0_windows-x64_portable.zip.sha256`です。GitHubが表示する「Source code」のZIPは開発用ソースで、実行用Portable ZIPとは別です。

Windows 10／11では、次の手順でPowerShellを開いて検証できます。

1. 取得したZIPと`.sha256`ファイルを同じフォルダーに置き、エクスプローラーでそのフォルダーを開きます。
2. ウィンドウ上部のアドレスバーに`powershell.exe`と入力し、Enterキーを押します。そのフォルダーでPowerShellが起動します。
3. 下のコマンドのファイル名を取得した版に合わせ、1行ずつ入力または貼り付けて、Enterキーで実行します。

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath .\DOL-Progress-Manager_0.3.0_windows-x64_portable.zip
Get-Content -LiteralPath .\DOL-Progress-Manager_0.3.0_windows-x64_portable.zip.sha256
```

表示されたHashと、`.sha256`の先頭64桁が一致することを確認します。英字の大文字・小文字は区別しません。ZIP内のSHA256SUMS.txtは、EXEと同梱文書の4ファイルを照合するための一覧です。hashの一致はファイルの整合性確認であり、入手先の正当性を単独で保証するものではありません。

実行ファイルはAuthenticode未署名です。Windowsから発行元を確認できない等の警告が表示される場合があります。配布元、Releaseの説明、hashを確認したうえで実行を判断してください。保護機能を恒常的に無効化する必要はありません。ソースのGit署名は、EXEのAuthenticode署名とは別です。

### 展開・起動と使用許諾

1. 書き込み可能な新しいフォルダーへZIP全体を展開します。ZIP内から直接実行しないでください。
2. 展開した`dol-progress-manager.exe`を起動します。
3. 初回の使用許諾を読み、「表示された利用条件を確認し、同意します」にチェックを入れます。
4. 「同意する」を押します。通常起動して必要なデータ・設定フォルダーが作成されます。

通常起動後は「プロフィール」画面へ進み、[プロフィールの作成](#プロフィールの作成)を行います。データベースと設定フォルダーの場所は、必要に応じて「保存場所」画面で確認できます。

README.txt、LICENSE.txt、THIRD-PARTY-NOTICES.txt、SHA256SUMS.txtはEXEと一緒に保持してください。外部Runtime、インストーラー、進捗DB、設定、マスターデータはZIPに含みません。

使用許諾で「同意しない／終了する」を押すか、画面を閉じた場合は起動しません。同じ配置で有効な同意記録がある場合は、次回から画面を省略します。

Program Filesや読み取り専用フォルダー等で書き込めない場合は、アプリを終了し、フォルダー全体を書き込み可能な場所へ移動してください。管理者としての実行やACL変更は標準の解決手順にしません。データ保存先をAppDataへ自動で切り替えることもありません。

### プロフィールの作成

キャラクターごとにプロフィールを作成します。通常起動後に最初に開くのは「プロフィール」画面です。

1. 「プロフィール」画面で「プロフィールを作成」を押します。
2. 「プロフィール名」を入力します。「メモ（任意）」は空欄でも構いません。
3. 「保存」を押します。作成したプロフィールが自動で選択されます。

プロフィール作成とマスターデータ取り込みは、どちらを先に行っても構いません。進捗を登録するには、対象のマスターデータと選択中のプロフィールが必要です。

### マスターデータの取得と取り込み

マスターデータは、クエストや発見物の名前・説明・関連などの元情報です。元のCSVはこのリポジトリや配布対象のソースに同梱しません。[大航海時代データベース](https://gvdb.mydns.jp/db/)から、クエスト用の`quests.csv`と発見物用の`discovery_items.csv`を自身で手動取得してください。アプリの「マスターデータ」画面にある「大航海時代データベースを開く（外部サイト）」からもサイトを開けます。

取得したファイルを、次の手順で取り込みます。

1. 「マスターデータ」画面を開き、「quests.csv を選択」を押します。
2. 取得した`quests.csv`を選び、表示されたファイル名・データセット・SHA-256・解析行数を確認します。この時点ではデータベースを更新しません。
3. 「クエスト情報を更新」を押し、「クエストマスターを更新しました。」と件数が表示されるまで待ちます。
4. 「discovery_items.csv を選択」から発見物用のファイルを選び、同じように内容を確認します。
5. 「発見物情報を更新」を押し、「発見物マスターを更新しました。」と件数が表示されるまで待ちます。

2ファイルの取り込み順は固定されていません。両方を取り込むと、解決できるクエストと発見物の関連が反映されます。未登録のときは有効件数が0件で、「インポート履歴はありません。」と表示されます。更新後は「最近のインポート履歴」でも結果を確認できます。

警告がある場合は「警告の詳細を確認」を開きます。

ファイルは拡張子が`.csv`でもタブ区切りで、文字コードはCP932／Windows-31J互換です。取り込みではヘッダーと行を検証してから、マスターデータ・関連・取り込み履歴を一括更新します。途中で失敗した場合は更新を取り消します。利用者のプロフィールと進捗は保持します。詳しくは[データ取り込み](docs/data-import.md)を参照してください。

アプリは大航海時代データベースの自動ダウンロード、スクレイピング、バックグラウンド更新、同サイトへの書き込みを行いません。利用状況を外部へ自動送信する機能、進捗の外部送信、自動更新機能も実装していません。サイトを開く操作は、固定URLを既定のブラウザーで開きます。開発時のViteサーバーや依存関係の取得は、通常アプリのオフライン利用とは別です。

#### 取り込みに失敗したとき

文字コード、ヘッダー、行データなどに問題がある場合は、エラーとその詳細を表示します。次の項目を確認してください。

1. クエスト用の`quests.csv`を「quests.csv を選択」から、発見物用の`discovery_items.csv`を「discovery_items.csv を選択」から選んでいるか確認します。
2. エラーに行番号や項目名が表示されている場合は、その内容を確認します。
3. エラーの内容と取り込むファイルを確認してから、上のファイル選択ボタンで選び直します。表示された内容を確認し、「クエスト情報を更新」または「発見物情報を更新」を押します。

「このファイルは既にインポートされています。」と表示された場合は、「最近のインポート履歴」と各マスターの有効件数を確認してください。

### 最初の進捗登録

「現在のプロフィール」が記録したいキャラクターになっていることを確認し、記録する対象に合わせて進んでください。

- クエストの達成から記録する場合は、[クエストの達成状態を変更する](#クエストの達成状態を変更する)の手順を使います。関連する発見物も連動して登録されます。
- 発見物から記録する場合は、[発見物の状態とカード所有を変更する](#発見物の状態とカード所有を変更する)の手順を使います。関連クエストがある場合の選択・連動も確認してください。

登録後は「概要」で進捗を確認できます。

## 基本操作

### プロフィールの選択と編集

- キャラクターを切り替えるときは「現在のプロフィール」から選ぶか、「プロフィール」画面の一覧で名前を押します。クエスト・発見物の進捗はプロフィールごとに分かれています。
- 名前やメモを変更するときは、対象プロフィールの「編集」を押し、入力して「保存」を押します。
- プロフィールの「削除」は、そのプロフィールのクエスト・発見物進捗も削除します。確認画面で「削除する」を押すと取り消せません。

編集できるメモはプロフィールの「メモ（任意）」です。クエスト・発見物の名前の横にある情報ボタンは、取り込んだ説明・備考を表示するもので、個別メモの編集画面ではありません。

### クエストの達成状態を変更する

1. 「クエスト」画面で、記録するクエストを検索します。
2. 「達成」のチェックを入れると達成済み、外すと未達成になります。

新たに達成済みにしたときは、有効な関連発見物のうち、進捗が未登録のものも発見済みにします。既存の発見物進捗は上書きしません。達成を取り消しても、連動して登録された発見物の進捗は戻りません。保存済みのクエストメモがある場合は、未達成へ戻すと削除されます。

「地図の状態」は、達成チェックとは別に関連発見物の状態を変更する欄です。[地図の状態と初回報告](#地図の状態と初回報告)を参照してください。

### 発見物の状態とカード所有を変更する

報告状態の操作は、発見物の種類によって異なります。普段の報告には「報告状態」欄を使います。

| 発見物の種類 | 「報告状態」欄の操作 |
| --- | --- |
| 通常の発見物 | チェックを入れると報告済み、外すと未報告になります。 |
| 地図に関連する発見物 | 自動報告対象とレリック以外は、選択欄から現在の状態を選びます。[地図の状態と初回報告](#地図の状態と初回報告)を参照してください。 |
| 自動報告対象 | 状態を表示するだけで、手動の報告操作はありません。発見済みなら「報告済み（自動）」と表示します。 |
| レリック | 「対象外」です。 |

1. 「発見物」画面で対象を検索し、「発見状態」のチェックを入れます。
2. 報告したら、上の表に従って「報告状態」を変更します。
3. カードを手放した場合は「カード所有」のチェックを外します。再び所有した場合はチェックを入れます。

通常の新規発見は、未報告・カード所有の状態で登録されます。報告とカード所有は独立して変更でき、未発見の間はどちらも操作できません。レリックのカードも「対象外」です。

有効な関連クエストが1件だけなら、発見の登録に合わせてそのクエストも達成済みにします。複数ある場合は「関連クエストを選択」で、達成済みにする1件か「クエスト進捗は変更しない」を選び、「発見済みにする」を押します。「キャンセル」では登録しません。

報告チェックを外す操作は、再発見後の未報告状態を記録するためのものです。確認後も過去の報告履歴は保持します。過去の初回報告を訂正する操作とは区別してください。

発見チェックを外して未発見へ戻す場合は、確認画面が表示されます。現在の発見・報告・カード所有・維持設定と、保存されている発見物メモを削除します。クエスト達成、過去の報告履歴、旧バージョンから引き継いだ冒険勲功値の算入資格は保持します。

### 地図の状態と初回報告

| 項目 | 意味と使い分け |
| --- | --- |
| 現在の報告状態 | 今の発見・報告状況です。再発見してまだ報告していない場合は「未報告」にします。過去の報告履歴は消しません。 |
| 地図の初回報告 | 地図から発見できる発見物を、過去に一度でも報告したかを表します。現在の報告状態とは別に管理します。 |

再発見後の未報告を記録する場合は、初回報告のチェックを外さず、現在の「報告状態」を変更してください。

地図に関連する発見物では、「発見物」画面の「報告状態」欄から「未発見」「未報告」「報告済み」を選びます。「クエスト」画面の「地図の状態」欄からも関連発見物を操作できます。複数の発見物が関連する地図は、関連発見物を確認する画面から対象を選びます。同じ発見物に対応する地図は、その発見物の状態を共有します。

変更内容の確認が表示された場合は、内容を読み「記録を保存」を押します。未発見へ戻すときの削除範囲は、発見チェックを外す場合と同じです。レリックは対象外で、自動報告対象は状態を表示するだけになります。

「地図の初回報告」のチェックや、不明な履歴を確認するボタンから、過去の実績を確認・訂正できます。表示される冒険勲功値への影響を確認し、「記録を保存」を押します。現在報告済みのものを初回報告前へ訂正する場合は、現在状態も未報告または未発見へ訂正する方法を選ぶ必要があります。未発見への訂正ではカード所有・発見物メモなども削除されます。

この履歴操作は、地図に関連する報告対象の発見物に限ります。レリックや自動報告対象には提供されません。

### 検索・絞り込みと詳細情報の表示

- 「クエスト名／地図名を検索」「発見物名を検索」に名前の一部を入力して検索します。
- クエストは達成状態、前提クエスト、オファー方法・都市、必要スキル、発見物、地図の入手などで絞り込めます。発見物は分類、状態、未報告の内訳、カード所有、地図などで絞り込めます。
- 並べ替えボタンのある列見出しを押すと、その列で並べ替えます。クエストでは選択したスキルの「要求Rank」でも並べ替えできます。
- 「前ページ」「次ページ」で移動し、「1ページの件数」で50件または100件を選びます。
- 名前の横の情報ボタンを押すと、取り込んだ説明・備考を表示します。情報がない場合はボタンを表示しません。

### 概要で進捗を確認する

「概要」画面で、選択中プロフィールのクエスト達成数、発見数、現在未報告、カード所有、冒険勲功値、発見物分類別の集計を確認できます。対象は現在有効なマスターデータです。

発見物の主な集計ではレリックを分けて表示し、総発見数も併記します。カード所有率は、カード対象の発見済み発見物を分母にします。冒険勲功値は算入対象の経験値から算出した参考値で、経験値が未登録の発見物は合計に含みません。

分類や「未報告の発見物一覧を開く」「カード未所有の発見物一覧を開く」から、対応する条件で絞り込んだ「発見物」一覧へ移動できます。

## データと設定の保存場所

標準の構成は次のとおりです。`data`と`config`は初回起動時に必要に応じて生成されます。

```text
DOL-Progress\
  dol-progress-manager.exe
  data\
    dol-progress.db
  config\
    consent.json
    data-root.json
    data-root.last-good.json
```

`data`内のSQLiteデータベースには、プロフィール、クエスト・発見物の進捗、メモ、取り込んだマスターデータ等を保存します。`config`には初回同意の記録（`consent.json`）、保存場所の設定と復旧情報を保存します。通常、設定ファイルを手編集する必要はありません。

保存先はEXEの親フォルダーを基準に決まり、カレントディレクトリに依存しません。異なるEXEフォルダーは別々の標準DBを使用します。

Windowsでは同じログオンセッションでの多重起動を防止します。保存先やアプリの配置が異なっても、
既に起動している場合は「アプリケーションは既に起動しています。」と通知して終了します。
別の配置で使う場合は先に起動したアプリを終了してください。この機能を持たない旧版や別Windowsセッションには適用されないため、旧版との同時利用は避けてください。

「保存場所」画面は「データベース」と「アプリの設定」を別のカードに分け、それぞれデータベースのフォルダーと設定フォルダーを表示します。保存場所の変更はデータベースだけが対象です。設定フォルダーはアプリのフォルダー内にあり、カスタムDBへ移行しても移動しません。カスタム利用時にはデータベースのカードに「カスタム保存先を使用しています」と補足します。

「データとアプリの管理」カードには、データベースのバックアップ、ファイルの移動と編集、アプリ削除の案内をまとめています。Windows側に残るデータの説明は別のカードに表示します。

| 保存方式 | 現在のデータベース | 設定フォルダー |
| --- | --- | --- |
| 標準 | アプリのフォルダー内の`data/dol-progress.db` | アプリのフォルダー内の`config` |
| カスタム | 選択した外部フォルダー直下の`dol-progress.db` | アプリのフォルダー内の`config` |

カスタムへ変更する場合は「データベースの保存場所を変更」からローカル固定NTFS上の外部の空フォルダーを選び、「このフォルダーへデータベースを移行する」を実行します。アプリのフォルダー、その内部、その親フォルダーは選べません。検証済みのデータを移行して再起動し、元のデータベースは安全コピーとして残します。元のコピーと使用中のDBは、その後の更新が同期されません。

設定されたDBが見つからない場合や、カスタム保存場所を確認できない場合は復旧画面を表示します。別の場所に空DBを自動作成しません。保存場所を修正した後は、アプリを一度終了して起動し直してください。詳細は[データ保存場所の仕様](docs/data-root.md)を参照してください。

WebView2のキャッシュやブラウザー用データは、Windows側のユーザーデータ領域（LocalAppData）に残る場合があります。進捗を保存する`data`や保存場所を記録する`config`とは別です。「Windowsに一切何も残さない」構成ではありません。

WebView2のユーザーデータの保存場所は`%LOCALAPPDATA%\com.dolprogress.manager`です。異なるEXEコピーも同じWindowsユーザーではこの場所を共有するため、複数フォルダーからの同時起動は現時点の保証対象としません。

## バックアップと復元

### 内蔵バックアップ

アプリ実行中は「マスターデータ」画面の「バックアップを作成」を使います。現在使用中のデータベース全体から整合したバックアップを作り、選んだ場所へ保存します。標準・カスタムのどちらでも同じ操作です。設定フォルダー自体は含みません。アプリのフォルダーを削除しても残る別の場所へ保存してください。

### バックアップから復元する

1. 「マスターデータ」画面で「復元するファイルを選択」を押し、バックアップを選びます。
2. 表示されたファイル名と検証結果を確認します。
3. 現在のデータベース全体を置き換えることを確認して、「復元する」を押します。復元中はアプリを終了しないでください。

現在のプロフィール、クエスト・発見物の進捗、マスターデータはバックアップ時点の内容に置き換わり、成功後に再起動します。保存方式は切り替わりません。

対応するバックアップは、データベースの更新履歴がバージョン1〜4の正規のもので、履歴・必要な構造・整合性・外部キーの検証に合格したものです。旧バージョンからの復元後は、再起動時に必要なデータベース更新を適用します。互換性と失敗時の手順は[バックアップ／リストア仕様](docs/backup-restore.md)を参照してください。

### 終了後のフォルダーバックアップ

アプリを完全に終了してから、アプリのフォルダー全体を別の場所へコピーします。標準利用なら、本体・data・configをまとめて保管できます。実行中の`dol-progress.db`だけを手作業でコピーする方法は使わないでください。

カスタム利用では、アプリのフォルダーをコピーするだけでは外部DBを保管できません。内蔵バックアップで現在のDBを別途保存してください。外部フォルダーもまとめて保管する場合は、アプリを完全に終了してからコピーします。

## アプリの更新

画面下部のバージョン番号からアプリケーション情報を開き、「更新を確認」を押すと、GitHubでLatestに指定された通常版と比較できます。パネルを開くだけでは通信しません。確認時はGitHubへ接続し、IPアドレス等の通常の通信メタデータが伝わり得ます。プロフィールや進捗データ、認証トークンは通信に付加しません。

対象のWindows x64 ZIPと外部SHA-256ファイルが掲載されている新版だけを「更新あり」と案内します。すべてのリリースの中でバージョン番号が最大のものや、配布物の安全性・ハッシュ照合を保証する表示ではありません。「GitHub Releasesを開く」から既定ブラウザーで一覧を開き、取得・検証・更新は手動で行ってください。

自動確認・自動ダウンロード・自動インストールは行わず、通信失敗時も基本機能をオフラインで利用できます。通常の確認間隔は60秒で、GitHubの利用制限時はさらに待つ必要があります。

更新するときは、次の手順でデータを保護してください。

1. 更新前に内蔵バックアップを保存します。
2. DOL Progress Managerを完全に終了し、必要ならフォルダーバックアップも保管します。
3. GitHub Releasesから更新先のPortable ZIPと外部`.sha256`を取得し、[ダウンロードとファイルの確認](#ダウンロードとファイルの確認)の手順でハッシュを確認して、既存のアプリとは別の新しいフォルダーへ全体を展開します。
4. 展開したEXEと同梱文書だけを既存のアプリのフォルダーへコピーして更新します。既存の`data`と`config`、カスタム保存先のDBは保持します。**data/configを削除・上書きしないでください。**
5. 再起動し、「保存場所」画面とプロフィール・進捗を確認します。

新しい空のdata/configで既存データを置き換えないことが原則です。

## アプリのフォルダーの移動

アプリを完全に終了してから、フォルダー全体を移動します。標準ではdataとconfigも一緒に移動し、新しいアプリの場所を基準に使用します。EXEだけを移動しないでください。

カスタムではconfigはアプリと一緒に移動しますが、外部DBの絶対パスは変わりません。外部フォルダーは自動で移動しません。移動後も同じ場所へアクセスできることを確認してください。

## アプリの削除

アプリ本体を削除する場合は、完全に終了してから`dol-progress-manager.exe`を削除します。アンインストーラーはありません。データベースや設定を残す場合は、「保存場所」画面でそれぞれの場所を確認し、そのファイル・フォルダーを削除しないでください。アプリのフォルダー全体を削除する必要はありません。

標準利用でアプリのフォルダー全体を削除すると、data/configも削除され、進捗データを失います。削除前にバックアップを別の場所へ保存してください。

カスタム利用では外部DBは通常残りますが、アプリのフォルダー内の設定は消えます。再導入時はカスタム保存場所の設定をやり直す必要があります。既存DBが残ることだけに頼らず、削除前に内蔵バックアップも保存してください。WebView2 Runtimeを一緒に削除する必要はありません。

## 旧版からの移行と既存カスタム保存場所

旧開発版等からは、内蔵バックアップを保存し、新しいアプリで復元する手順で移行します。

1. 旧版で「バックアップを作成」を実行して、別の場所へ保存します。
2. 旧版を完全に終了します。
3. ポータブル版を起動し、「復元するファイルを選択」で保存したバックアップを検証します。
4. 確認後に「復元する」を実行します。再起動後にプロフィール・進捗を確認します。
5. カスタムを使う場合は、「保存場所」画面で外部の空フォルダーへ移行します。

旧AppDataのDBや設定を探索・自動移行する処理はありません。旧版の設定ファイルを手編集・コピーして切り替える手順や、実行中DBの単体コピーは推奨しません。

ポータブル版の既存configを保持してアプリのフォルダーを移動・更新する場合は、外部カスタム保存場所をそのまま使います。旧版と新版を同じDBへ同時に接続しないでください。

### 復旧画面で既存の保存場所を指定し直す

「設定されているデータ保存場所を開けません。」と表示されている場合に、既存のカスタムDBがある外部フォルダーを再指定する手順です。

1. 復旧画面の「保存場所を指定し直す」を押し、既存のカスタムDBがある外部フォルダーを選びます。
2. 「検証済みの保存場所を使用する」を押します。

ローカル固定NTFS等の条件とDBの互換性検証を満たす必要があり、成功後に再起動します。この操作は復旧画面に限ります。

通常画面の「データベースの保存場所を変更」は空フォルダーへの移行用で、既存DBに直接切り替える操作ではありません。新規導入時は上記のバックアップ／復元手順を使ってください。

## 困ったとき

| 状況 | 確認・対処 |
| --- | --- |
| 起動できない、Runtimeの不足を案内される | [動作環境と必要な準備](#動作環境と必要な準備)を確認し、必要なRuntimeを導入して起動し直します。VC++ Runtime不足ではアプリ内の案内が表示できない場合があります。 |
| 書き込みができない | アプリを終了し、フォルダー全体を書き込み可能な場所へ移動します。管理者実行やアクセス権変更を標準の解決手順にはしません。 |
| マスターデータがなく一覧を使えない | 「マスターデータ」画面から[取り込み手順](#マスターデータの取得と取り込み)を実行します。 |
| マスターデータの取り込みに失敗する | [取り込みに失敗したとき](#取り込みに失敗したとき)で、ファイルの種類とエラー内容を確認します。 |
| プロフィールを選択するよう案内される | 「プロフィール」で作成するか、「現在のプロフィール」から対象を選びます。 |
| 検索結果が空になる | 検索語と絞り込み条件を確認し、変更します。 |
| 保存場所の復旧画面が表示される | [復旧画面で既存の保存場所を指定し直す](#復旧画面で既存の保存場所を指定し直す)を参照します。保存場所の仕組みは[データと設定の保存場所](#データと設定の保存場所)で確認できます。 |
